# 접속기록 화면 점검 — 2026-11-11

아래 가독성 개선은 2026-11-11 운영에 반영했다. 적용 및 검증 범위: [운영 배포 기록](release-2026-11-11.md).

## 이번 적용

- 접속기록 메뉴의 상단 큰 제목을 ‘접속기록 점검 현황’, 하단 조회 영역의 큰 제목을 ‘접속기록’으로 구분한다.
- 최근 3개월 요약은 실제 요청 ID가 있는 월만 표시한다. 승인 대기/승인/반려/회수 등 실제 요청 상태는 유지한다. 요청하지 않은 월을 가상 행으로 만들지 않는다. 데이터 조회 실패와 이력 없음은 구분한다.
- 하단 표의 첫 열을 접속일시로 고정하고 한국 시간의 날짜·시·분·초를 표시한다.

## 검토 결과 및 후속 개선안

현재 AdminAudit는 RPC 응답 키를 열 이름으로 사용하고, 객체 값을 JSON 문자열로 출력한다. API는 사용자/조직 UUID, action 코드, target_type/target_id, 결과 코드, metadata 등을 반환한다. 로그 저장/조회는 동작하더라도 점검자가 누가 언제 어떤 대상을 처리했는지 쉽게 읽기에는 부족하다.

권장 목록 열은 ‘접속일시(KST) / 사용자(이름·이메일·소속·계정 식별자) / 접속 IP / 수행업무 / 처리 대상 / 처리 결과 / 상세’다. 고정된 한국어 제목, 작업·결과 코드 번역, 이름/조직명 조회를 적용하고 현재 정보인지 기록 당시 정보인지 명시한다. 원본 식별자·요청 ID·metadata 등은 상세에 보존한다. 이름이 바뀌거나 계정이 비활성화된 경우에도 사용자 ID로 추적할 수 있어야 한다.

현재 검색은 작업·사용자/조직/대상 ID·결과·요청 ID 중심이다. 날짜 범위·이름/이메일·접속 IP·업무 유형·성공/차단 조건의 서버 검색이 필요하다. 시스템/세션 내부 이벤트와 개인정보 열람·변경 등 업무 이벤트를 구분해 점검할 수 있어야 한다.

`audit.append_access_log`의 IP는 신뢰된 내부 호출자가 제공할 때만 기록한다. 게이트웨이 감사 이벤트 등에는 IP가 있지만 모든 업무 append가 이를 전달하지는 않는다. 조회 화면에서 빈 IP를 정상 IP로 추정하거나 임의의 과거 기록에 연결해서는 안 된다. 검증된 게이트웨이 요청과 업무 이벤트의 연결을 보완해야 한다.

`target_id`는 Ticket/Profile/Organization 등의 업무 객체 ID다. 이것이 처리한 정보주체의 식별정보를 충분히 나타내는지 별도로 검증해야 한다. 상세 조회 RPC는 개인정보 포함 여부 등 일부 metadata를 기록하지만 모든 목록/직접 조회/파일 다운로드가 일관되게 같은 감사 체인에 수집되는지는 보장되지 않는다. 인증 공급자의 비밀번호 로그인 실패도 앱 감사 기록과 별도다. 화면 정비만으로 수집 범위나 보관·무결성 요건을 충족한다고 판단하지 않는다.

## 법령 참고 범위

국가법령정보센터의 「개인정보의 안전성 확보조치 기준」(제2026-9호) 제2조제3호는 접속기록을 식별자, 접속일시, 접속지 정보, 처리한 정보주체 정보, 수행업무 등을 전자적으로 기록한 것으로 정의한다. 이 검토는 이를 바탕으로 화면과 소스의 확인 가능성을 살핀 것이며 운영 데이터 전체 또는 법적 준수에 대한 확정 판정은 아니다.

공식 원문: https://law.go.kr/admRulLsInfoP.do?admRulSeq=2100000281400

후속 순서: (1) 고정 한국어 목록/상세 화면과 검색 (2) 사용자·조직의 서버 조회 보완 (3) 검증된 IP 및 정보주체 식별 연결과 수집 누락 검증. 과거 원본 로그·감사 해시는 재작성하지 않는다.

## 목록 가독성 적용

고정 열 ‘접속일시(KST) / 접속 사용자 / 접속 IP / 수행한 업무 / 처리 대상 / 처리 결과 / 상세보기’를 실제 구현했다. 현재 이름·이메일·조직명은 기존 인증/RLS 게이트웨이의 profiles/organizations 조회로 보완하므로 새 DB 조회 함수 배포 전에도 로컬에서 표시할 수 있다. 비활성 계정을 제외하는 조건은 추가하지 않는다. 조회가 실패하면 사용자 ID와 원본 로그는 유지하고 사용자 정보 조회 실패를 표시한다.

기록 당시 이름·이메일이 반환되면 우선 표시하며 각 항목의 출처를 표기한다. 조직은 당시 명칭 스냅샷, 기록된 소속 ID의 현재 명칭, 현재 사용자 소속 순으로 확인 가능한 값을 표시하고 출처를 구분한다. 안정된 사용자 ID는 목록에 계속 표시한다. 주요 작업·인증·점검 이벤트 및 결과 코드를 한국어로 번역하고 알려지지 않은 코드는 ‘기타 업무/결과’로 표시하며 상세에서 원문을 확인한다.

상세보기에는 원본 로그·계정·인증계정·조직·대상·요청 ID, 작업/결과 원본 코드, 순번·해시·원본 metadata를 보존한다. 과거 로그 자체는 수정하지 않는다.

`20261111000003_readable_access_audit.sql`은 같은 조회 RPC의 서명·Company Admin/앱 세션 검사를 유지하면서 당시 필드·현재 사용자/조직명·원본 증적 필드를 반환하고 이름·이메일·IP 검색도 지원한다. DB 미반영 상태에서 기존 RPC가 반환하지 않는 과거 이름/이메일·해시 등의 필드는 추정하지 않으며 ‘기록 없음’이다. 현재 사용자 정보 조회와 한국어 고정 열 표시는 기존 API로도 동작한다.
