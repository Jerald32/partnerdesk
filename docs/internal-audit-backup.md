# 회사 내부 저장장치에 보관하는 접속기록 백업

회사는 별도 클라우드 계정·저장소를 추가하지 않고 내부 저장장치로 백업 파일을 다운로드한다. 사내 DRM 적용을 전제로 하되, 해당 JSON 파일이 DRM 정책의 보호 대상인지 실제 저장 후 확인한다. DRM을 적용했다는 사실만으로 백업 누락·복구 가능성·원본 무결성까지 보장되지는 않는다.

## 이용 방법

1. Company Admin이 ‘접속 기록’ 메뉴의 ‘사내 저장장치 백업’에서 기간과 사유를 입력한다. 기본 기간은 한국 시간 기준 전일이다.
2. 브라우저의 ‘다운로드 전 저장 위치 확인’을 켜고 ‘사내 보관용 백업 다운로드’를 누른다. 회사가 지정한 내부 저장장치를 선택한다. 앱에서 PC/NAS 경로를 강제로 지정하거나 백그라운드로 저장하지 않는다.
3. 실제 파일의 존재·크기와 사내 DRM 적용을 확인한 뒤 체크하고 ‘사내 보관 확인 기록’을 누른다. 이는 요청한 관리자의 확인 진술이며 앱이 파일 저장 위치나 DRM 상태를 자동 검증했다는 기록이 아니다.
4. ‘저장한 백업 파일 무결성 확인’에서 파일을 선택한다. 내부 데이터의 SHA-256·건수 검증 후 서버의 발급 기록과 대조한다. DRM이 파일 바이트를 변경했다면 사내 정책에 따라 정상 복호화된 원본을 검증한다. 원본 파일 전체는 검증 서버로 다시 업로드하지 않고 백업 ID와 해시만 전달한다.

## 범위 및 한도

- 화면 검색·페이지 조건과 무관하게 선택한 한국 시간 날짜 범위의 접속기록 원본 전체를 포함한다. 원본 metadata·ID·순번·체인 해시를 유지하며 현재 화면 표시용 이름/코드로 원본을 재작성하지 않는다.
- 대상 월이 겹치거나 해당 기간에 요청/처리된 점검의 요청·결정과 전체 고정 대상 ID 연결을 포함한다. 연결된 접속기록이 선택 기간 밖에 있으면 그 원본 이벤트는 별도 기간 백업에 있으므로 파일 scope에 이를 명시한다. 일별 파일만으로 특정 월을 복원할 때는 해당 월 전체 파일과 이후 점검/승인 파일도 함께 보관해야 한다.
- 회사가 보관하는 JSON은 업무 DB 전체의 재해복구용 SQL 덤프가 아니다. 사용자 계정·운영 설정 등을 포함한 전체 시스템 복구는 Supabase DB 백업 등 별도 절차가 필요하다.
- 한 번에 최대 31일, 접속기록 10,000건, 점검 요청 10,000건, 점검 대상 ID 연결 100,000건, 직렬화 원본 2MiB를 지원한다. 한도 초과 시 일부 데이터를 파일로 저장하지 않고 실패한다. 짧은 기간으로도 초과하면 대용량 분할 내보내기를 별도로 준비해야 한다.
- 파일은 원본 JSON 문자열과 SHA-256을 가진 `partnerdesk-audit-backup-v1` 봉투다. 해시는 원본 UTF-8 JSON 문자열 기준이며 파일의 들여쓰기 등 봉투 자체는 검증 대상 원문과 구별한다. 내부 체크섬만으로 전자서명이나 법적 적합성을 보장한다고 주장하지 않는다.

## 운영 권장안

전일 기록을 매일 다운로드하고 담당자 부재 시 대체자를 정한다. 누락일을 정기 확인하며 월별 점검 후 승인 이력이 포함된 백업도 보관한다. 이 주기는 운영 권장안이며 실제 내부 관리계획에 반영해야 한다. 보존기간·백업 접근자·DRM 정책·복구 시험 주기를 회사 정책으로 정한다. 백업 파일 자체도 개인정보를 포함할 수 있다.

정기 복구 시험은 격리된 환경에서 수행하고 원본 건수·범위·해시 및 점검 대상 ID 연결을 확인한다. 이번 구현에서는 파일 생성과 검증을 테스트했으며 운영 DRM 적용과 실제 사내 장치 저장·전체 시스템 복원은 검증하지 않았다. SHA 검증은 브라우저 또는 `node scripts/verify-audit-backup.mjs <복호화된 원본 파일>`로 수행한다.

## 반영

`20261111000004_internal_audit_backup.sql` 및 선행 월별 점검 마이그레이션을 적용한 뒤 게이트웨이 허용 목록과 프론트엔드를 배포한다. 새 역할이나 별도 클라우드 계정은 만들지 않는다. 앱 세션과 활성 Company Admin 검사를 서버에서 수행한다. 파일 생성과 관리자의 보관 확인은 별도 감사 이벤트이며 보관 확인 중복 요청은 한 건으로 처리한다. 실제 백업 파일이나 사내 저장 경로는 서버에 재저장하지 않는다.
