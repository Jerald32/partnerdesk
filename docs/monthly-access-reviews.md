# 월별 접속기록 점검 승인

## 이용 흐름

- 전역 관리자(활성 Company Admin)가 접속기록 화면의 ‘접속기록 점검 승인요청하기’ 또는 사이드바 ‘월별 접속기록 점검’으로 이동한다.
- 전월을 기본으로 지난 달의 대상 월을 고르고 점검 결과·특이사항·조치 내용을 입력한다. 특이사항/조치가 없으면 없다는 사실을 명시한다.
- 본인을 제외한 활성 Company Admin/Operator 중 로그인 계정이 연결된 사용자 1명을 승인자로 지정한다. Partner, Guest, 비활성 사용자는 제외한다.
- 요청 시 승인자에게 앱 내 알림을 보내고, 한국 시간 기준 대상 월의 전체 접속기록 ID 목록을 확정한다. 검색 조건이나 현재 화면의 한 페이지만 대상으로 하지 않는다.
- 승인자는 알림 또는 `/access-reviews`에서 배정된 건을 열고, 점검 결과와 고정된 접속기록을 확인한다. 검토 의견을 입력해 승인 또는 반려한다.
- 승인 시 해당 월을 완료 처리한다. 반려 시 보완해 재요청할 수 있다. 전역 관리자는 처리 전 요청을 사유와 함께 회수하고 승인자를 바꿔 재요청할 수 있다.
- 전역 관리자는 전월 승인 미완료 안내를 확인할 수 있다. 자동 승인이나 자동 요청은 하지 않는다.
- 기본 현황은 점검 대상 월 기준으로 전월까지 최근 3개월을 표시한다. ‘전체보기’(`/access-reviews?view=all`)에서는 기간 제한 없이 조회한다. 전체보기의 ‘뒤로가기’는 최근 3개월 현황으로 이동한다. 조회 범위는 서버에서 페이지 처리 전에 적용하며 전체보기에서도 기존 사용자별 조회 권한을 유지한다.

## 권한과 증적

접속기록 화면과 월별 점검 기본 화면에는 최근 3개월 중 실제 점검 요청 이력이 존재하는 월만 요약 표에 표시한다. 서버는 각 월의 최신 요청 상태를 별도로 집계하며, 화면은 요청 ID가 없는 월을 제외한다. 이력이 없으면 빈 상태 안내, 조회 실패 시에는 오류 안내를 표시하며 전체보기와 다시 조회하는 경로를 제공한다. 전역 관리자 외 사용자에게는 이 전체 월별 요약을 반환하지 않는다.

새 역할을 추가하지 않는다. 전역 관리자만 요청·회수할 수 있으며 지정 승인자만 해당 건을 승인·반려할 수 있다. 요청자 본인 승인은 금지한다. 지정 승인자는 기존 접속기록 전체 조회 API에 접근할 수 없고 자신에게 배정된 월별 점검의 고정된 기록만 읽는다. 조회와 처리 시 현재 계정·Company 소속·앱 세션을 다시 검증한다.

요청/결정/대상 기록 연결은 `audit` 스키마의 별도 테이블에 저장하며 직접 SELECT/INSERT 권한은 주지 않는다. UPDATE/DELETE/TRUNCATE도 차단한다. 결정은 요청당 한 번만 가능하다. 월별 트랜잭션 잠금으로 승인 대기·승인 완료의 중복 요청을 차단한다. 이전 반려·회수 요청은 보존한다.

대상 기록의 원본 ID·순번·해시를 유지한다. 나중에 과거 월의 기록이 추가되더라도 이미 제출한 점검 범위에는 포함하지 않는다. 이름·이메일은 현재 프로필에서 조회한 값임을 안내하며 사용자 ID는 요청/결정에 보존한다. 검증된 게이트웨이 접속 IP만 저장하고 없으면 기록 없음으로 표시한다.

요청·승인·반려·회수·상세 조회는 기존 감사 체인에 기록한다. 요청/결정·알림·감사 append는 같은 트랜잭션이며 실패하면 함께 롤백한다. 점검 내용·의견 원문을 접속기록 metadata에 중복 복사하지 않는다.

## 적용

`20261111000002_monthly_access_reviews.sql` 적용 후 새 RPC 허용 목록을 포함한 게이트웨이와 프론트엔드를 배포한다. notifications에 새 컬럼/유형이 필요하므로 DB를 먼저 반영한다. 이전 작업의 `20261111000000`, `20261111000001`도 미반영 상태라면 순서대로 먼저 적용한다. 기존 사용자 역할·접속기록을 변경하거나 실제 사용자에게 테스트 알림을 보내지 않는다.

화면: `/access-reviews`, `/access-reviews/:id`. 월별 점검의 기록은 기존 접속기록 화면과 연결되며, 요청·승인 알림에서 해당 점검으로 이동한다.

운영 DB 적용 및 운영 관리자/승인자 브라우저 종단 간 확인은 별도이다. 본인 승인 금지, 대상 월 고정, 지정자 외 조회/승인 차단, 반려·회수 후 재요청, 이력 불변, 감사 실패 시 롤백을 실제 PostgreSQL 게이트웨이 테스트로 검증한다.
