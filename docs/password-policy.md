# 비밀번호 생성·변경 정책 — 2026-11-09

사용자 승인: 최소 8자, 영문 대문자·소문자·숫자·특수기호 각각 1개 이상.
공백 및 한글은 특수문자로 계산하지 않는 수준이 아니라 비밀번호 어디에도 포함할 수 없다.
한글 완성형·자모, 탭·줄바꿈·Unicode 공백도 검사한다. 비밀번호를 임의로 trim하지 않는다.
기존 인증 엔진의 UTF-8 최대 72바이트 한도를 화면과 서버에서 같이 검사한다.

## 서버 강제

- 운영 Auth 설정 두 필드만 최소 길이 8 / 네 가지 문자 집합으로 변경했다.
- 기본 Auth 설정은 금지 문자 전체 제외를 지원하지 않으므로 가입·재설정은 `password-policy` Edge 검증을 거친다.
- 화면과 Edge가 같은 `src/lib/password.js`를 사용한다.
- 검증을 통과한 비밀번호의 bcrypt 해시를 2분짜리 서버 전용 일회성 승인으로 연결한다.
  DB에는 평문 비밀번호를 저장하지 않는다. 가입 승인은 이메일·무작위 증명에, 재설정 승인은 검증된 사용자 ID에 묶인다.
- `auth.users` 저장 트리거가 승인된 해시만 저장하고 승인을 소비한다.
  기본 Auth API 직접 호출, 증명 위조·재사용으로 금지된 비밀번호를 저장할 수 없다.
- 가입 증명은 사용자 metadata에서 제거한다. 가입 동의·이메일 확인·복구 토큰 정리·Auth 세션 처리는 기존 native Auth 흐름을 사용한다.
- 일반 JWT 검증 없이 타인의 비밀번호를 변경할 수 없다. 입력의 userId/role은 사용하지 않는다.
- 요청 제한은 해시 계산 전에 적용한다. 가입 이메일별 3회/시간·전체 30회/시간, 재설정 사용자별 6회/시간이다.

기존 로그인 비밀번호를 일괄 변경하지 않는다. 비밀번호 변경 시 기존 앱 세션 철회 및 변경 시각 기록은 기존 트리거가 수행한다.
90일 강제 변경·유출 비밀번호 검사·추가 재인증 설정은 이번 범위가 아니다.
90일 경과 시 로그인 후 안내하고 본인 재설정 메일을 요청하는 기능은 별도 [분기별 비밀번호 변경 안내](password-cycle-notice.md)로 적용했다.

## 운영 절차

`scripts/password-policy.ps1 -Mode Inspect`는 정책 필드만 조회한다.
`Apply`는 Auth 최소 길이·필수 문자만 반영하고 나머지 설정이 같음을 확인한다.
`Probe`는 native Auth의 필수 조건 거부, `ProbeEndpoint`는 전용 API의 공백·한글 포함 거부를 확인한다.
비밀번호·토큰을 채팅이나 로그에 기록하지 않는다.

관리자 도구를 포함한 비밀번호 생성·변경은 검증 API를 사용한다. 일반 native Auth 쓰기는 서버 승인 없이는 거부된다.
장애 복구 시 운영자가 `private.password_policy_config.enforced=false`로 일시 해제할 수 있으나
이 경우 기본 문자 조합만 강제되고 공백·한글 전체 금지는 보장되지 않는다. 정상 운영에서는 true를 유지한다.
Auth의 해시 알고리즘·work factor·암호화 설정을 바꾸기 전에 저장 보호와 재해시 동작을 함께 검토한다.

## 검증

- 격리 DB: 승인 없는 가입·변경 거부, 이메일 결합, 일회성·만료, 승인 해시 저장, RPC 권한, 요청 제한.
- 운영 DB: `verify-password-policy-rollback.sql`에서 강제 플래그·임시 사용자·동의·변경을 모두 ROLLBACK하며 동일 동작 확인.
- 운영 API: native 필수 조건 7종 및 전용 API 10종의 거부 확인.
- 실사용자 비밀번호를 변경하거나 실제 신규 가입·메일 수신 테스트를 수행하지 않았다.

참고: [Supabase 비밀번호 보안](https://supabase.com/docs/guides/auth/password-security).
