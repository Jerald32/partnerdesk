# 권한 변경 이력 가독성 개선

2026-11-11 운영 반영 완료. 상세: [운영 배포 기록](release-2026-11-11.md).

권한 변경 이력의 컬럼은 변경일시(KST, 날짜와 시·분·초), 변경 대상자(이름·이메일·변경 후 소속),
변경 전 권한, 변경 후 권한, 변경자(이름·이메일·현재 소속) 순서다.
직접 변경/요청 승인은 상세보기에 표시한다. 검색어(이름·이메일·소속), 한국 시간 기준
시작일/종료일, 처리 방식으로 서버에서 검색하며 페이지당 100건을 표시한다.

상세보기에는 요청 시각, 신청 사유, 승인 메모, 원본 식별자와 처리 경로를 표시한다.
목록에는 신청자(이름·이메일·신청 소속), 신청일시, 신청사유, 변경자의 접속 IP,
발급사유를 추가한다. 신청자와 대상자를 각각 조회하며, 신청이 없는 직접 변경은
‘신청 없음’으로 표시한다. 발급사유가 없으면 승인 메모를 출처와 함께 표시한다.
직접 변경에 대한 별도 사유 입력 기능은 기존에 없으며 해당 기록은 ‘기록 없음’이다.
IP는 새 INSERT 트리거에서 동일 트랜잭션·사용자·앱 세션에 묶인 검증된 gateway
nonce의 IP만 기록한다. 요청 헤더나 조회자의 IP를 사용하거나 과거 값을 추정하지 않는다.
기록 당시 이름/이메일이 있으면 우선하며 없는 항목은 현재 프로필로 보완한다.
조직명도 현재 정보를 연결한 값으로 안내한다. 누락된 정보는 추정하지 않는다.
기존 감사 이벤트를 수정하거나 개인정보 스냅샷을 추가 저장하지 않는다.

신규 RPC `search_admin_role_audit`는 유효한 앱 세션과 Company Admin을 요구한다.
일반 사용자와 service_role의 직접 실행은 허용하지 않는다. 게이트웨이의 RPC
허용 목록에 이 조회만 추가하며, 기존 접속/파기 이력 API는 유지한다.

반영 순서: `20261111000000_readable_role_audit.sql` 및
`20261111000001_role_audit_trusted_ip.sql` 마이그레이션을 먼저 적용한 뒤
게이트웨이와 프론트엔드를 배포한다. 운영 반영과 실제 관리자 화면 확인은 별도다.

검증: 권한/소속 차이 표시, KST, 조회 필터, 동일 시각 정렬, 두 번째 페이지,
레거시 소속 식별자, 신청 사유/메모, 실행 권한 및 앱 세션/관리자 검사를 테스트한다.
